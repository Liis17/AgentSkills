# Модели и роли

## Разрешённые маршруты

Разрешены только OpenAI через официальный Codex и Anthropic через официальный Claude Code. Провайдера и harness проверяй по каталогу T3, а не по отображаемому имени. OpenRouter и OpenCode запрещены для всех ролей, включая запасные маршруты.

## Таблица ролей

Строка задаёт семейство, минимальную версию и обязательный effort. Выбирай новейшую доступную стабильную версию семейства, а не фиксированный релиз. Знак `+` — нижняя граница.

| Роль | Семейство и минимум | Effort |
| --- | --- | --- |
| Ревью плана при основном агенте Anthropic | Sol 6.1+ (OpenAI/Codex) | medium |
| Ревью плана при основном агенте OpenAI | Opus 5.5+ (Anthropic/Claude Code) | medium |
| Исполнитель по умолчанию: код, проверки, исправления | Luna 5+ (OpenAI/Codex) | max |
| Альтернативный исполнитель | Haiku 5.5+ (Anthropic/Claude Code) | high |
| Независимое ревью большого, сложного или рискованного кода | Sonnet 5+ (Anthropic/Claude Code) | high |
| Необязательный эксперт сложной диагностики | Sol 6.1+ / Opus 5.5+, по возможности другой провайдер | medium |

- Luna max — сознательный выбор пользователя. Не снижай effort ради экономии.
- Haiku допустим в четырёх случаях:
  - пользователь отдаёт приоритет Claude;
  - Luna недоступна;
  - Haiku лучше подходит для задачи;
  - нужно распределить расход между квотами.
- Не запускай обоих исполнителей на одно задание «на всякий случай». Без подтверждённых данных о квотах выбирай Luna и не утверждай, что T3 показывает остатки лимитов.

## Каталог и кеш

- Вызови `orchestrator_capabilities` один раз в начале рабочей сессии. Сохрани проверенные `providerInstanceId`, model ID, опции и ограничения и используй их повторно, а не вызывай каталог для каждого агента.
- Если каталог сокращён (`omittedModels`), найди нужные семейства поиском: короткая выдача не доказывает, что более новой модели нет.
- Обновляй каталог в таких случаях:
  - сменился провайдер или конфигурация;
  - произошла ошибка доступности;
  - пользователь просит свежие модели;
  - перед делегированием после долгого простоя.

## Выбор модели

1. Определи семейство и версию по метаданным каталога, а при их отсутствии — по однозначной структуре официального model ID. Совпадения подстроки в отображаемом имени недостаточно. Неоднозначную принадлежность считай неподтверждённой.
2. Сравнивай версии численно по компонентам: `6.10 > 6.5`, недостающие компоненты считай нулями. Новая major-версия того же семейства подходит. Preview, nightly и beta исключены без разрешения пользователя.
3. Оставь варианты, которые проходят все фильтры: официальный harness, минимальная версия, доступность дочерних задач, реальная поддержка нужного effort. Из них выбери новейший. Проверяй имена опций: обычно у Codex `reasoningEffort`, у Claude — `effort`. Не подменяй max, high и medium другим уровнем.
4. Если подходящей модели или уровня нет, используй только альтернативу той же роли из таблицы. Иначе сообщи пользователю ограничение и дождись решения для зависимого шага. Не обходи обязательное ревью, не выдумывай ID и не меняй провайдера или семейство без согласования.
5. Передавай реальные `providerInstanceId`, `model` и настройки в `target.options` вызова `delegate_task`, а не текстом в задании. Сверь возвращённые провайдер, модель и опции. Несовпадение — ограничение, а не успех.

Роли требуют явного effort, поэтому делегируй через T3 `delegate_task`: нативные субагенты ненадёжно передают параметры модели. `inheritedOptions` учитывай только для того же провайдера и модели, явно задавая effort роли. Не включай `fastMode` и другие платные настройки без оснований. Создавай дочерние задачи, а не отдельные беседы через `t3_thread_launch` или `create_threads`.
