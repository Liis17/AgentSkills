# AGENTS.md — Оркестрация v2

Вызов: `$agents-md-orchestration`. Результат — самодостаточные инструкции
в корневом `AGENTS.md`, а не выполнение задач проекта. Сам вызов установщика
не требует субагентов. При запросе обновить исходники самого навыка редактируй
навык, не устанавливай его правила в текущий проект без такого запроса.

Цель правил — экономить вызовы и контекст при сохранении качества:
динамические модели по семействам, один исполнитель для кода и тестов,
ревью по риску и diff, ограниченные повторы. Процесс определяется **исходным**
режимом сессии. Обычная сессия допускает самостоятельную реализацию;
сессия из Plan Mode требует межпровайдерного ревью плана, подтверждения
пользователем и реализации только через исполнителей.

## 1. Подтвердить T3 Code

Для установки и работы правил нужен успешный `orchestrator_capabilities`.
Найди инструмент в каталоге; если не виден, сделай одну прямую попытку
`mcp__t3_code__orchestrator_capabilities` (сервер может подключаться лениво).
Если MCP не доступен, но задан `T3_ACP_MCP_NODE`, используй транспорт T3:

```sh
ELECTRON_RUN_AS_NODE=1 "$T3_ACP_MCP_NODE" ${T3_ACP_MCP_ENTRYPOINT:+"$T3_ACP_MCP_ENTRYPOINT"} acp-mcp-call orchestrator_capabilities '{}'
```

Путь проекта, название модели и текущий `interactionMode` не заменяют
подтверждение возможностей. Если T3 или каталог подтвердить не удалось,
сообщи причину и останови установку, не меняя `AGENTS.md` и не переходя
к оркестрации другой среды. Редактирование исходников навыка само по себе
не является установкой или запуском этих правил.

## 2. Прочитать инструкции проекта

Определи корень через Git, иначе по указанной пользователем или текущей папке.
Прочитай корневой `AGENTS.md` и связанные с ним правила оркестрации.
Ищи существующие инструкции по смыслу: делегирование, роли, модели, субагенты.
Даже неполные правила считаются существующими.

Без явного запроса обновления сохрани существующие правила, сообщи их место
и пробелы; не дополняй их дублирующим блоком. При явном обновлении замени
существующий блок в его границах. Если правила находятся вне маркеров,
не перезаписывай их автоматически: выясни область обновления и конфликты.

## 3. Собрать самодостаточные правила

Прочитай все три справки и включи их содержимое в один блок в таком порядке:

1. [references/session-modes.md](references/session-modes.md) — исходный режим,
   официальные harness’ы, единая таблица ролей, динамический выбор и кеш каталога.
2. [references/plan-mode.md](references/plan-mode.md) — только для исходного
   Plan Mode: подготовка, независимое ревью другим провайдером, подтверждение.
3. [references/implementation.md](references/implementation.md) — код и тесты
   одним исполнителем, risk-aware/diff-aware ревью, tool-first диагностика,
   retry budget, параллелизм и компактный handoff для обоих режимов.

Таблица в первой справке — единственное определение моделей и effort.
Знак `+` задаёт нижнюю границу семейства, а не закрепляет последний релиз.
Не дублируй таблицу в остальных разделах и не заменяй её текущими model ID.
По каталогу проверь доступность нужных ролей и настроек. Если нужного варианта
нет, сообщи ограничение; не записывай вымышленные ID, неподтверждённые квоты
или молчаливую замену. Не утверждай доступность роли по одному её названию.

## 4. Установить или обновить один блок

Используй маркеры `<!-- agents-md-orchestration:start -->`
и `<!-- agents-md-orchestration:end -->`. Если файла нет, создай его.
Сохраняй содержимое и форматирование вне маркеров без изменений.
Не добавляй второй блок, не изменяй другие файлы проекта, не устанавливай
инструменты или модели. Не заменяй полные правила ссылками на локальный навык:
`AGENTS.md` должен работать без установленного навыка.

Повторный вызов без запроса обновления не меняет файл. При нескольких блоках
или повреждённых маркерах сначала установи безопасные границы обновления;
не удаляй окружающие инструкции. Существенный конфликт с действующими
правилами проекта разреши с пользователем до записи конфликтующей части.

## 5. Проверить результат

Проверь ровно одну пару маркеров, сохранность текста вне блока,
самодостаточность и отсутствие дублирующих определений. Проверь сценарии:

- Исходный Plan Mode: Anthropic → роль ревью Sol; OpenAI → роль ревью Opus,
  обе на medium; затем подтверждение пользователя до реализации.
- Новые стабильные Sol 6.5/6.10, Luna 7, Opus 6, Haiku 6 и Sonnet 6
  подходят без правки правил при наличии в T3 и поддержке effort;
  6.10 новее 6.5. Preview без разрешения не выбирается.
- Luna всегда max, Haiku high; отсутствующий effort не понижается молча.
- Код и проверки выполняет тот же исполнитель; NOT_RUN не равен PASS.
- Обычная сессия допускает самостоятельную работу; маленькая безопасная
  правка не создаёт ревьюера, высокая опасность требует независимой проверки.
- Две неудачные попытки не вызывают бесконечные циклы; эксперт только
  диагностирует, реальные статусы проверок сохраняются.

Сообщи путь и результат установки/обновления либо место существующих правил,
а также обнаруженные ограничения каталога. При редактировании навыка сообщи
изменённые файлы и выполненные проверки.
