# Правила и значения для проверки анимаций

Единый каталог для навыка `motion`. Значения в находках копируй отсюда, не приближай. Основано на подходе к анимации интерфейсов Emil Kowalski ([emilkowal.ski](https://emilkowal.ski/), [animations.dev](https://animations.dev/)).

## Порядок исправлений

Предлагай самое раннее подходящее исправление:

1. **Удалить анимацию** — частое действие, нет назначения, вызов с клавиатуры.
2. **Сократить** — короче длительность, меньше смещение, меньше анимируемых свойств.
3. **Исправить кривую** — `ease-in` → `ease-out` или сильная своя кривая.
4. **Исправить точку роста и физичность** — верный `transform-origin`; `scale(0)` → `scale(0.95)` + `opacity`.
5. **Сделать прерываемой** — keyframes → transition, для жестов — пружина.
6. **Перенести на GPU** — layout-свойства → `transform`/`opacity`; сокращения Framer Motion → полная строка `transform`; WAAPI для программной анимации.
7. **Асимметричное время** — медленно там, где решает пользователь, быстро там, где отвечает система.
8. **Полировка** — размытие на кроссфейде, stagger, `@starting-style`, пружина для «живых» элементов.
9. **Доступность и согласованность** — reduced-motion, ограничение hover, характер продукта.

## 1. Назначение и частота

Каждая анимация должна отвечать на вопрос «зачем это анимируется». Допустимые ответы:

- **Обратная связь** — интерфейс услышал пользователя: сжатие кнопки, заливка при удержании.
- **Пространственная связь** — откуда элемент пришёл и куда ушёл: тост входит и выходит с одного края, панель растёт из триггера.
- **Индикация состояния** — смена состояния читается: кнопка меняет форму, аккордеон раскрывается.
- **Без резкой смены** — контент не телепортируется, не появляется и не исчезает без перехода.
- **Объяснение** — показывает, как работает функция (только маркетинг и онбординг).
- **Радость** — только для редких моментов.

«Выглядит круто» на часто видимом элементе — не назначение.

| Частота | Решение |
|---------|---------|
| 100+ раз в день: сочетания клавиш, командная палитра, основная навигация | Без анимации. Никогда |
| Десятки раз в день: hover, навигация по списку, частые переключатели | Убрать или сделать почти незаметной |
| Иногда: модальные окна, панели, тосты, настройки | Обычная анимация |
| Редко или впервые: онбординг, пустые состояния, успех, празднование | Можно добавить радость |

Действия с клавиатуры не анимируются: их повторяют сотни раз в день, и анимация делает их медленными и оторванными от действия. У Raycast нет анимации открытия и закрытия — так и должно быть.

Искать: анимацию на клавиатурных действиях, переходы у командной палитры, декоративное движение у элементов списка и частых hover. Лучшее исправление здесь — удалить анимацию.

## 2. Кривые и длительность

Выбор кривой:

- Вход или выход → **`ease-out`**: начинается быстро, ощущается отзывчиво.
- Движение или изменение формы на экране → **`ease-in-out`**.
- Hover и смена цвета → **`ease`**.
- Постоянное движение (бегущая строка, прогресс) → **`linear`**.
- По умолчанию → **`ease-out`**.

**`ease-in` в интерфейсе — всегда находка.** Он начинается медленно и задерживает именно тот момент, на который смотрит пользователь. `ease-out` за 200 мс ощущается быстрее, чем `ease-in` за те же 200 мс.

Встроенные кривые CSS слишком слабые для осознанной анимации. Сильные кривые, оформленные токенами по соглашениям проекта:

```css
--ease-out: cubic-bezier(0.23, 1, 0.32, 1);        /* сильный ease-out для интерфейса */
--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1);    /* сильный ease-in-out для движения на экране */
--ease-drawer: cubic-bezier(0.32, 0.72, 0, 1);     /* кривая панели как в iOS (Ionic) */
```

Новые кривые берут с [easing.dev](https://easing.dev/) или [easings.co](https://easings.co/), а не подбирают вручную.

**Анимации интерфейса короче 300 мс.**

| Элемент | Длительность |
|---------|--------------|
| Отклик кнопки на нажатие | 100–160 мс |
| Подсказки, маленькие поповеры | 125–200 мс |
| Выпадающие списки, select | 150–250 мс |
| Модальные окна, панели | 200–500 мс |
| Маркетинг, объяснения | Может быть дольше |

Скорость влияет на восприятие производительности: выпадающий список за 180 мс отзывчивее, чем за 400 мс; быстрый спиннер делает загрузку субъективно быстрее; подсказки после первой открытой должны появляться сразу, без задержки и анимации.

Искать: `ease-in`, голые `ease`/`linear` на входе, длительности больше 300 мс в интерфейсе, задержку и анимацию у каждой подсказки в панели инструментов.

## 3. Физичность и точка роста

- **Никогда `scale(0)`** — в реальном мире ничего не появляется из ничего. Начало: `scale(0.9–0.97)` + `opacity: 0`.
- **Поповеры, меню и подсказки растут из триггера**, а не из центра:

  ```css
  .popover { transform-origin: var(--radix-popover-content-transform-origin); } /* Radix */
  .popover { transform-origin: var(--transform-origin); }                       /* Base UI */
  ```

  **Модальные окна — исключение:** они по центру экрана, `transform-origin: center` для них верен. Не отмечай его.
- **Отклик на нажатие:** `transform: scale(0.97)` на `:active` и `transition: transform 160ms ease-out`. Мягко: 0.95–0.98. Относится ко всем нажимаемым элементам.
- `scale()` масштабирует и детей (текст, иконки) — для отклика на нажатие это полезно.
- Проценты в `translate` считаются от размера самого элемента: `translateY(100%)` сдвигает на его высоту. Это лучше захардкоженных пикселей.

Искать: `scale(0)`, появление только через прозрачность, `transform-origin: center` или его отсутствие у элементов, привязанных к триггеру, нажимаемые элементы без отклика.

## 4. Прерываемость и асимметрия

CSS **transition** при прерывании продолжает с текущего состояния; **keyframes** начинаются заново с нуля. Всё, что срабатывает часто или может развернуться посреди движения (тосты, переключатели, перетаскивание, раскрытие и сворачивание), делается через transition или пружины.

```css
/* Прерываемая — для динамического интерфейса */
.toast { transition: transform 400ms ease; }

/* Не прерываемая — не для динамического интерфейса */
@keyframes slideIn { from { transform: translateY(100%); } to { transform: translateY(0); } }
```

Вход без JS — `@starting-style`:

```css
.toast {
  opacity: 1; transform: translateY(0);
  transition: opacity 400ms ease, transform 400ms ease;
  @starting-style { opacity: 0; transform: translateY(100%); }
}
```

Запасной вариант для старых браузеров: атрибут `data-mounted`, который ставится в `useEffect(() => setMounted(true), [])`.

**Пружины** сохраняют скорость при прерывании. Их используют для перетаскивания с инерцией, «живых» элементов, жестов, которые могут развернуться, и декоративного следования за мышью.

```js
{ type: "spring", duration: 0.5, bounce: 0.2 }              // как у Apple — рекомендуется
{ type: "spring", mass: 1, stiffness: 100, damping: 10 }    // физические параметры
```

Отскок мягкий: 0.1–0.3. Заметный отскок — только для смахивания и игривых моментов. Следование за мышью — через `useSpring`, а не прямую привязку к координатам, и только если эффект декоративный.

**Жесты:**

- Закрытие по скорости, а не только по расстоянию: `Math.abs(distance) / elapsedMs > ~0.11`.
- За естественной границей перетаскивание замедляется с ростом сопротивления, а не упирается в невидимую стену.
- После начала перетаскивания — pointer capture, чтобы оно продолжалось за пределами элемента.
- Лишние касания после начала перетаскивания игнорируются (`if (isDragging) return`).

**Асимметричное время:** осознанная фаза (нажатие, удержание, подтверждение удаления) идёт медленнее, ответ системы — быстро. Симметричное время у нажатия-отпускания или удержания — находка.

```css
.overlay { transition: clip-path 200ms ease-out; }            /* отпускание: быстро */
.button:active .overlay { transition: clip-path 2s linear; }  /* нажатие: медленно */
```

Искать: `@keyframes` у тостов, переключателей и частых элементов; жесты с keyframes фиксированной длительности; закрытие только по порогу расстояния; жёсткие упоры на границах.

## 5. Производительность

- **Анимируй только `transform` и `opacity`.** Они не вызывают перерасчёт layout и перерисовку и выполняются на GPU. `width`/`height`/`margin`/`padding`/`top`/`left` запускают все этапы отрисовки.
- **`transition: all`** анимирует лишние свойства вне GPU — всегда находка.
- **Сокращения Framer Motion `x`/`y`/`scale` не ускоряются аппаратно:** они идут через requestAnimationFrame в основном потоке и роняют кадры под нагрузкой.

  ```jsx
  <motion.div animate={{ x: 100 }} />                          // роняет кадры под нагрузкой
  <motion.div animate={{ transform: "translateX(100px)" }} />  // аппаратное ускорение
  ```

- **CSS-переменная на родителе, двигающая детей,** пересчитывает стили всех детей. Ставь `transform` прямо на элемент:

  ```js
  element.style.setProperty('--swipe-amount', `${d}px`); // плохо
  element.style.transform = `translateY(${d}px)`;        // хорошо
  ```

- CSS-анимации и WAAPI работают вне основного потока и не дёргаются, когда браузер занят. CSS — для заранее известного движения, JS и пружины — для динамического и жестов.
- WAAPI даёт управление из JS с производительностью CSS:

  ```js
  element.animate([{ clipPath: 'inset(0 0 100% 0)' }, { clipPath: 'inset(0 0 0 0)' }],
    { duration: 1000, fill: 'forwards', easing: 'cubic-bezier(0.77, 0, 0.175, 1)' });
  ```

- `filter: blur()` во время перехода — меньше 20px: сильное размытие дорогое, особенно в Safari.

Искать: `transition: all`, анимацию layout-свойств, сокращения Framer Motion на нагруженных страницах, `setProperty('--…')` для transform детей, циклы requestAnimationFrame там, где хватило бы CSS.

## 6. Доступность

```css
@media (prefers-reduced-motion: reduce) {
  .element { animation: fade 0.2s ease; } /* оставить прозрачность и цвет, убрать движение */
}
@media (hover: hover) and (pointer: fine) {
  .element:hover { transform: scale(1.05); } /* на тач-экранах касание вызывает ложный hover */
}
```

```jsx
const reduce = useReducedMotion();
const closedX = reduce ? 0 : '-100%';
```

Reduced motion — это меньше и мягче, а не ноль. Переходы, помогающие понять интерфейс, остаются; смещения и движение убираются.

Искать: движение без `prefers-reduced-motion`, hover-анимацию без ограничения, реализации reduced-motion, которые убирают вообще всю обратную связь.

## 7. Согласованность и токены

- Анимация соответствует характеру продукта: игривое может пружинить, рабочая панель остаётся чёткой и быстрой. Один пружинящий компонент в строгом приложении — находка.
- Кривые и длительности хранятся общими токенами. Пять почти одинаковых вручную набранных `cubic-bezier` — находка на объединение.
- Группа элементов, появляющаяся разом, — stagger 30–80 мс между элементами. Stagger декоративный и не блокирует взаимодействие.

  ```css
  .item { opacity: 0; transform: translateY(8px); animation: fadeIn 300ms ease-out forwards; }
  .item:nth-child(2) { animation-delay: 50ms; }
  .item:nth-child(3) { animation-delay: 100ms; }
  @keyframes fadeIn { to { opacity: 1; transform: translateY(0); } }
  ```

- Кроссфейд, в котором видны два наложенных состояния, маскируется лёгким `filter: blur(2px)` на время перехода.
- `clip-path: inset(t r b l)` — инструмент для раскрытия при прокрутке (`inset(0 0 100% 0)` → `inset(0 0 0 0)`), заливки при удержании, плавной смены цвета вкладок и слайдеров сравнения.
- Прозрачность + высота у появляющихся элементов списка не имеет формулы — проверяется только на ощущение.

Искать: дубли кривых и длительностей, выбивающийся по характеру компонент, списки без stagger, кроссфейды с двойным изображением.

## 8. Упущенные возможности

Каждый кандидат проходит четыре вопроса по порядку. Не прошёл любой — отклонён.

1. **Частота.** По таблице раздела 1. 100+ раз в день и клавиатурные действия — отказ без обсуждения. Десятки раз — отказ или почти незаметное движение.
2. **Назначение.** Одно из названий раздела 1. Если назвать нельзя — отказ. «Радость» — только для редких моментов.
3. **Бюджет.** Укладывается в длительности раздела 2. Если момент работает только как медленная эффектная анимация — отказ.
4. **Польза.** Данные, которые пользователь читает или с которыми работает, не двигаются ради стиля. Декоративное следование за мышью уместно на маркетинговой странице, но не на графике в банковском приложении.

Где искать:

- **Нет обратной связи:** нажимаемые элементы без `:active` → `transform: scale(0.97)`, `transition: transform 160ms ease-out`. Удаление одним кликом там, где удержание предотвратило бы ошибку → оверлей `clip-path: inset(0 100% 0 0)`, 2s linear при нажатии, 200ms ease-out при отпускании.
- **Телепортация состояния:** условный рендер, смена контента маршрута, раскрывающиеся секции без перехода → вход из `scale(0.95–0.97)` + `opacity: 0`, `ease-out`, `@starting-style`. Аккордеоны, открывающиеся рывком. Элементы списка, добавляемые без перехода, — через transition, не keyframes.
- **Нет пространственной связи:** панели и меню без связи с триггером → рост из `transform-origin` триггера (модальные окна — по центру). Тосты и шторки, выходящие не так, как вошли → один край, `translateY(100%)`.
- **Групповое появление:** сетка или список, появляющиеся разом на редко видимой странице → stagger 30–80 мс.
- **Жесты:** перетаскиваемые элементы без физики → пружина `{ type: "spring", duration: 0.5, bounce: 0.2 }`, закрытие по скорости, сопротивление на границах.
- **Бюджет радости:** первый запуск, пустые состояния, успех, празднование, оформленные плоско. Только здесь уместны отскок, щедрый stagger и более длинная пауза.

Поиск: условный рендер без перехода (`{isOpen &&`, переключение `display: none`), `onClick` на элементах без `:active` и transition, `details` и аккордеоны, обработчики перетаскивания, `.map(` для появляющихся списков, компоненты пустых состояний и успеха.

## Проверка ощущения

Когда по коду нельзя судить, рекомендуй:

- **Замедление** в 2–5 раз или инспектор анимаций DevTools: цвета переходят чисто, кривая не обрывается, точка роста верная, связанные свойства синхронны.
- **По кадрам** — панель Animations в Chrome DevTools показывает расхождение связанных свойств.
- **Реальное устройство** для жестов: открыть dev-сервер по IP с телефона, Safari remote devtools.
- **Свежий взгляд на следующий день** — недочёты, незаметные во время разработки, видны позже.
